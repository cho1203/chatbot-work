# 기본 챗봇 시스템 정의 및 구축 안내

문서 버전: 1.0 / 작성일: 2026-09-18 / 신규 시스템 명칭: `base-chatbot`

작성 시 수행한 확인과 실제 구축 단계에 남겨 둔 확인은 [검증 기록](./VALIDATION.md)에 정리했다.

## 1. 이 문서로 만드는 시스템

운영자가 봇을 만들고 문서 또는 Q&A를 등록하면, 사용자가 웹 화면에서 질문하고 등록한 자료에 근거한 답변과 출처를 받는 한국어 중심 챗봇을 만든다. 근거가 부족한 질문은 미답변함으로 모으고, 운영자가 답변을 등록하면 다음 검색부터 사용할 수 있게 한다.

이 문서는 네 기존 앱을 그대로 복제하는 설명서가 아니라 **새 앱 하나의 규범적 개발 명세**다. 기존 구현에서 얻은 설계와 신규 개선 사항은 [출처·설계 결정](./10-reference-and-decisions.md)에서 구분한다. 본문의 “해야 한다”는 신규 구현의 필수 계약이다.

현재 `mvbot`에는 참고 문서가 있고, 아래에서 지정하는 `app/`, `migrations/`, `tests/` 등 신규 앱은 아직 구현되어 있지 않다. 실행 명령은 해당 단계에서 파일과 기능을 작성한 **새 프로젝트 루트**에서 사용한다. 문서만으로 이미 작동하는 배포물이 있다는 뜻은 아니다. 설치·모델 추론·성능을 검증한 결과와 개발 시 통과해야 할 기준을 구별한다.

## 3. 기본 선택과 선택 기능

| 항목 | 기본 선택 | 바꾸는 조건 |
|---|---|---|
| 언어·서버 | Python 3.11, FastAPI, Uvicorn 1 worker | GPU/패키지 호환 검증 후 변경 |
| 화면 | Jinja2 + 로컬 CSS + 순수 JavaScript | UI가 복잡해지면 React 등으로 분리 |
| 업무 DB | SQLite + SQLAlchemy + Alembic | 다중 서버·쓰기 경합 시 PostgreSQL |
| 벡터 저장소 | Chroma PersistentClient, 봇별·세대별 컬렉션 | 다중 프로세스 접근 시 서버형 저장소 |
| 생성·임베딩 | Ollama `qwen3:4b`, `bge-m3` | 한국어 평가와 장치 용량 기준으로 변경 |
| 입력 | TXT, MD, CSV, DOCX, 텍스트 PDF, 수기 Q&A | 스캔·이미지·HWPX·XLSX는 확장 프로필 |
| 검색 | 벡터 + 정확 명칭 보강 + 키워드 재정렬 | 실패 사례를 모아 BM25·reranker 추가 |
| 전송 | POST fetch + SSE | HTTP JSON 응답도 같은 서비스 사용 |
| 실행 | 한 API 프로세스 안의 영속 작업 처리 루프 | 큐·검색 저장소 분리 후 다중 서버 |
| 외부 공개 | 초기값 비공개, 운영자가 명시적으로 공개 | 비공개 자료에는 공개 링크 사용 금지 |

모델명은 신규 개발의 시작 예시다. 기존 시스템의 운영 모델과 동일하다고 주장하지 않는다. 내려받을 때 모델 digest를 기록하고 재현에는 digest를 사용한다. 모델 태그 제공 여부는 공식 [qwen3:4b](https://ollama.com/library/qwen3:4b), [bge-m3](https://ollama.com/library/bge-m3)에서 확인했다. 필요한 RAM/VRAM은 실제 양자화·문맥 길이·동시성으로 측정한다.

## 4. 완료 수준

**L0 개발 기반:** 설정 검증, 마이그레이션, 인증, liveness/readiness가 동작한다.

**L1 기본 챗봇:** 기본 여섯 입력 유형, 원본 보존, 봇 간 격리, 검색, 근거 없는 질문 처리, 출처, 웹 채팅, 미답변 개선, 문서 수정·삭제·재색인, 재시작 후 복구를 검증한다.

**L2 공개 운영:** HTTPS, 세션·CSRF, 요청 제한, 관리 권한, 프록시 SSE, 백업 복원, 평가셋, 장애 시나리오를 검증한다. L1을 달성해도 L2 검증 전에는 외부 공개하지 않는다.

**L3 선택 확장:** OCR, 정밀 표·그림, 한국어 HWPX, BM25·cross encoder, 외부 LLM, 조직 권한, 다중 서버를 필요에 맞게 추가한다. 선택 기능은 해당 인수 기준까지 통과해야 “지원”으로 표시한다.

## 5. 주요 용어

| 용어 | 의미 |
|---|---|
| RAG | 검색한 자료를 생성 모델에 제공하여 답변하는 방식 |
| 문서 버전 | 원본 또는 Q&A의 변경 불가능한 한 사본 |
| 블록 | 페이지·문단·표·그림 단위의 추출 결과 |
| 청크 | 임베딩과 검색에 사용하는 크기의 텍스트 조각 |
| 인덱스 세대 | 한 시점의 봇 전체 지식으로 만든 검색 스냅샷 |
| 색인 | 청크 임베딩을 벡터 저장소에 넣는 작업. 모델 학습과 다름 |
| 미답변 | 시스템은 정상이나 자료로 답할 수 없는 질문 |
| 장애 | 자료 존재 여부와 별개로 추출·검색·모델·저장이 실패한 상태 |
| 근거 점수 | 검색 순위 결정용 값. 답변 정답 확률이 아님 |

## 6. 새 프로젝트에서 먼저 결정할 여섯 값

도메인 이름, 자료 관리자, 최초 자료 목록, 대표 질문 20개, 공개 범위, 실행 장치를 `PROJECT_DECISIONS.md`에 기록한다. 나머지는 본문 기본값으로 시작한다. 사용자 질문에 없는 전문 업무, 결제·CRM·코드 실행 등을 기본 챗봇 개발에 끼워 넣지 않는다.

모든 수치 기본값과 평가 목표는 새 시스템용 초기 제안이다. 실제 서비스에서 측정한 값으로 바꿀 때 변경 이유, 평가 결과, 적용 일자를 함께 남긴다.
