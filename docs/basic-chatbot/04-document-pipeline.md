# 04. 문서 수집·전처리·OCR·청킹

[목차](./README.md) · 이전: [데이터 계약](./03-data-contracts.md) · 다음: [검색](./05-index-and-retrieval.md)

## 1. 처리 원칙과 입력 범위

전처리는 읽을 수 있는 글자를 뽑는 작업으로 끝나지 않는다. **원문 사실, 문서 구조, 출처 위치, 처리 방법을 함께 보존하는 작업**이다. 원본을 덮어쓰지 않고 추출본·정규화본·청크를 구분한다. 웹 업로드와 일괄 적재 CLI는 동일한 `ingestion` 서비스를 사용한다.

| 형식 | 기본 처리 | 출처 위치 | 기본판 한계·확장 |
|---|---|---|---|
| TXT | UTF-8/BOM, CP949 순으로 명시적 디코딩 | 줄 범위 | 모두 실패하면 검토, 무조건 errors=ignore 금지 |
| MD | 제목·문단·목록·코드 블록 보존 | 제목 경로·줄 범위 | HTML 실행 금지 |
| CSV | 첫 행 헤더, 행별 열이름: 값 | 원본 행 번호 | 대용량·중복 헤더 처리 필수 |
| DOCX | 문단·표의 원래 문서 순서 | 문단/표/행 인덱스 | 페이지는 추측하지 않음 |
| 텍스트 PDF | pypdf 페이지별 추출 | 물리 페이지·가능하면 쪽수 라벨 | 스캔·다단·정밀 표는 검토 또는 확장 |
| 수기 Q&A | 질문·답변을 하나의 지식 단위로 저장 | 문서 ID·버전·Q&A 항목 | 답변 수정은 새 버전 |
| 스캔 PDF·PNG/JPEG | 선택 OCR 프로필 | 페이지·bbox·엔진·인식 품질 | OCR 없으면 지원 불가로 명확히 반환 |
| XLSX | 선택 openpyxl 프로필 | 시트명·셀/행 | 수식 실행 금지, 저장된 값 사용 여부 고지 |
| HWPX | 선택 ZIP/XML 어댑터 | 섹션·문단·표 | 구조 시험 필요 |
| HWP·DOC | 격리된 변환기로 PDF/DOCX 변환 | 원본과 변환본 연결 | 변환기 지원 확인 전 허용하지 않음 |

pypdf는 OCR 엔진이 아니며 PDF의 시각적 배치와 추출 텍스트 순서가 다를 수 있다. 스캔 여부와 레이아웃 문제를 별도로 처리한다. 근거: [pypdf 텍스트 추출 설명](https://pypdf.readthedocs.io/en/stable/user/extract-text.html).

## 2. 업로드 전 검증

1. 봇 소유권, 봇·문서 상태, 파일 수와 크기를 확인한다. 기본 1요청 1파일, 20MiB, 최대 200페이지다.
2. 확장자, MIME, 실제 파서로 열 수 있는 구조를 함께 검사한다. Content-Type 헤더만 믿지 않는다.
3. 업로드 중에도 누적 바이트 상한을 검사한다. `Content-Length`가 없어도 적용한다.
4. 이름에서 경로를 사용하지 않는다. 원본을 서버 생성 경로에 저장하고 SHA-256을 계산한다.
5. DOCX/HWPX/XLSX의 ZIP은 항목 수 10,000·총 압축 해제 200MiB·압축률 100배를 초기 상한으로 둔다. 경로 이탈·암호 ZIP을 거부한다.
6. 암호화 PDF는 기본판에서 `encrypted_document`로 거부한다. 파일 암호를 로그에 남기는 우회 구현을 하지 않는다.
7. 파서 단계의 시간·메모리 제한을 둔다. 일반 추출 120초, 전체 작업 600초를 시작값으로 사용한다. 무거운 변환·OCR은 종료 가능한 하위 프로세스에서 수행한다.

검증 실패는 413/415/422 또는 작업 실패 코드로 구별한다. 202 접수 응답은 검색 가능 완료가 아니다. 관리자 화면은 작업 상태를 조회해야 한다.

## 3. 추출 어댑터 계약

아래는 구현할 인터페이스다. 클래스명과 DTO를 `schemas.py`에 정의하고 각 파서를 독립 시험한다.

```python
from pathlib import Path
from typing import Protocol

class Extractor(Protocol):
    def extract(self, path: Path, version_id: str) -> dict:
        """03장의 extracted.json 스키마와 동일한 객체를 반환한다."""
        ...
```

파서는 `blocks`에 원래 순서대로 결과를 넣는다. 글자가 없는 페이지도 문서의 페이지 수와 `empty_pages`에 남긴다. PDF의 빈 페이지를 없애고 페이지 번호를 다시 매기지 않는다. 추출 중 경고가 있었다면 `warnings`와 품질 검사 결과에 넣는다.

### TXT·MD

원본 줄 번호를 부여한 뒤 디코딩·정규화를 적용한다. UTF-8-SIG로 BOM을 먼저 처리하고 CP949를 시도한다. 바이너리 제어문자 비율이 높거나 디코딩이 불명확하면 `needs_review`로 보낸다. Markdown 제목은 `section_path`에, 코드 펜스 안 내용은 `type=code`로 보관한다. 링크 주소는 자료로 저장하되 추출기가 자동으로 방문하지 않는다.

### DOCX

문단을 모두 읽은 뒤 표를 뒤에 몰아 붙이지 않는다. document body의 paragraph/table 노드를 순회하여 읽기 순서를 유지한다. 목록 수준과 제목 스타일을 section_path로 변환한다. 병합된 표 셀은 원래 좌표와 병합 범위를 남기며 빈 셀을 옆 셀 값으로 자동 채우지 않는다. 텍스트 상자·머리글·각주가 누락될 수 있는 자료는 경고와 검토 대상으로 표시한다.

### CSV

구분자는 쉼표를 기본으로 하고 사용자가 탭·세미콜론을 지정할 수 있게 한다. 자동 탐지는 미리보기에서 확인한다. 헤더가 비거나 중복되면 `column_1`, `이름__2` 같은 결정적 내부 열 이름을 만들고 원본 헤더도 보존한다. 헤더보다 긴 행·짧은 행을 조용히 잘라내지 말고 경고한다.

한 행은 `제품명: A-100 | 온도: -10~50 °C | 비고: 실내용`처럼 열 이름과 단위를 함께 직렬화한다. 큰 CSV는 스트리밍으로 읽고 기본 최대 100,000행에서 중단한다. 검색 청크는 행 단위 또는 적은 수의 인접 행을 사용하며 각 청크에 헤더를 반복한다. CSV 출력·다운로드를 추가할 때 스프레드시트 수식으로 해석될 수 있는 입력을 별도 처리한다.

### PDF

페이지별 native 추출을 먼저 수행한다. 본문과 반복 머리말·꼬리말의 구별은 문서 전체 반복 빈도를 보고 판단한다. 문서 좌표를 지원하는 확장 파서에서는 원본 bbox를 보존한다. 특정 매뉴얼의 본문 Y좌표 100~775처럼 고정된 값을 모든 PDF에 적용하지 않는다.

텍스트가 적다는 이유만으로 무조건 OCR하지 않는다. 표지·그림 전용·실제 공백 페이지일 수 있다. 초기 분류 기준은 “이미지 면적이 크고 비공백 문자 30개 미만” 등으로 두되 문서별 평가로 조정한다. 현재 파서가 이미지 면적을 측정하지 못하면 단순히 `possible_scan` 경고를 내고 검토한다.

## 4. OCR 확장 구현 순서

OCR이 필요 없는 기본판을 먼저 완성한다. OCR 프로필을 켤 때 `OCR_ENGINE`, 엔진 버전, 장치, 언어, 렌더 DPI, 시간 제한을 별도 설정으로 추가한다. 기본판에 없는 설정을 문서만 추가하고 실제로 지원한다고 표시하지 않는다.

1. 엔진을 독립 가상환경/컨테이너에 설치한다. 예: Tesseract 한국어+영어 또는 PaddleOCR 한국어 모델. 패키지·모델·GPU 런타임을 별도 잠금한다.
2. PDF 페이지를 200~300 DPI로 렌더한다. 이미지 한 변·총 픽셀 수에 상한을 두고 방향·기울기를 보정한다.
3. 페이지 단위 native/OCR을 선택한다. 일부 페이지만 스캔인 혼합 PDF에서 전체 내용을 두 번 합치지 않는다.
4. OCR 결과를 글상자·읽기 순서·confidence·엔진 정보와 함께 저장한다. 서로 다른 엔진의 confidence를 같은 확률 척도로 섞지 않는다.
5. 표의 행·열을 복원하고 원본 캡처와 연결한다. 숫자 `0/O`, `1/l`, 소수점, 음수, 단위를 검토 항목으로 표시한다.
6. 추출 텍스트와 원본 이미지를 나란히 보여주고 관리자가 승인·수정한다. 수정도 버전과 감사 기록을 남긴다.
7. 승인된 추출본에 기존 chunker/indexer를 적용한다.

OCR 추론과 생성 모델이 같은 GPU를 쓰면 작업 스케줄러에서 자원 슬롯을 공유하거나 별도 서비스로 격리한다. 모델 선택 버튼이 다른 서비스를 `systemctl stop`하는 설계를 기본판에 가져오지 않는다.

HWPX는 ZIP 안전성 검사 후 섹션 XML을 원문 순서로 읽는 어댑터로 구현한다. HWP는 변환 도구가 실제 파일을 지원하는지 먼저 시험한다. 변환기는 `shell=False`, 인수 배열, 전용 임시 디렉터리, 타임아웃으로 실행한다. 변환 실패를 빈 텍스트 성공으로 반환하지 않는다.

## 5. 정규화 규칙

허용: Unicode NFC, 줄바꿈 LF 통일, 본문 밖 제어문자 제거, 연속된 공백 줄을 두 줄로 축소, 확인된 반복 머리말 제거. 원본과 정규화 텍스트 간 위치 매핑을 유지한다.

금지: 숫자·단위·부정어 삭제, 영문 식별자의 대소문자 일괄 변경, 제품 코드의 하이픈 제거, 표의 모든 셀을 문장처럼 병합, 다른 페이지의 문장을 근거 없이 연결, LLM 요약문으로 원문 대체.

표시용 원문은 보존하고 검색용 별칭만 별도 필드에 추가한다. 예를 들어 `고객 센터`와 `고객센터` 검색 확장은 가능하지만 원문을 고쳐 사실을 바꾸지 않는다. 민감정보 마스킹이 필요하면 원본 접근 권한과 검색용 마스킹본을 분리하고, 재식별 가능한 매핑은 일반 로그에 넣지 않는다.

## 6. 표와 그림의 구조

표 블록에는 `table_id`, `columns`, `rows`, `location`, `caption`을 저장한다. 검색에는 “표 제목 + 헤더 + 해당 행”을 사용하고 원형 JSON을 별도 보존한다. 긴 표 전체를 하나의 거대 청크로 만들지 않는다. 행이 길면 셀 경계를 우선 분할하되 행 ID·열 이름을 반복한다. 값이 없는 셀과 값이 0인 셀을 구별한다.

그림 블록에는 `asset_id`, 원본 문서 버전, page, bbox, caption, file_path를 저장한다. 기본판에서 그림을 추출하지 못하면 기능 지원 여부를 명시한다. 그림 설명을 모델로 생성하면 `caption_method=model`, 모델 버전, 검토 여부를 기록한다. 검토하지 않은 추론 설명을 원문 사실처럼 쓰지 않는다.

검색용 그림 청크는 주변 제목·검증된 캡션·페이지를 사용한다. 생성 모델에는 `F1` 같은 허용 ID 목록만 주고, 화면 URL은 서버가 실제 asset_id에서 생성한다. 모델이 임의 URL을 만들어 출처처럼 보이게 하지 않는다.

## 7. 청킹 알고리즘

기본 정책 이름은 `chunk-v1`, 최대 본문 1,000자, 겹침 목표 150자다. 문자 수는 토큰 수가 아니며 임베딩 입력 제한은 별도 검증한다.

1. 제목 경로와 종류가 같은 인접 텍스트 블록을 대상으로 한다. PDF는 기본적으로 페이지 경계를 넘지 않는다.
2. 문단 경계를 우선하여 조립한다. 다음 문단을 넣으면 상한을 넘을 때 현재 청크를 닫는다.
3. 긴 문단은 문장 경계로 나눈다. 문장 하나도 상한을 넘으면 코드포인트 기준으로 강제 분할한다.
4. 일반 본문만 같은 섹션·같은 페이지의 앞 청크 끝에서 최대 150자를 가져온다. 다음 조각을 붙인 **최종 결과가 1,000자를 넘지 않도록** 겹침을 줄이거나 다음 조각을 더 나눈다.
5. 표, Q&A, 코드 블록에는 일반 본문의 임의 겹침을 적용하지 않는다. 구조별 ID·헤더를 반복한다.
6. 최종 청크마다 참조 블록·줄/페이지 범위·ordinal을 기록한다. 빈 청크를 없애고 순서를 고정한다.
7. `embed_text`에 문서 제목과 섹션 경로를 붙인다. 이 접두사도 임베딩 입력 길이에 포함한다.

의사코드:

```text
for structural_group in source_order:
    pieces = split_to_bounded_pieces(structural_group)
    buffer = []
    for piece in pieces:
        while overlap + piece가 상한을 초과:
            overlap를 줄이거나 piece를 더 작은 의미 단위로 분할
        if buffer + piece가 상한을 초과:
            emit(buffer와 원본 위치)
            buffer = 허용된 overlap
        append(piece)
    emit(남은 buffer)
```

이 코드는 설계용 의사코드다. 구현 시험에는 공백 없는 5,000자, overlap=0, 정확히 상한 길이, 매우 긴 표 행, 이모지·한글, 페이지 경계, 제목만 있는 블록을 포함한다. 출력이 입력 정보를 누락하지 않는지 원문 위치로 확인한다.

Q&A는 질문과 답변을 함께 보존하고 `embed_text = 질문 + "\n" + 답변`으로 만든다. 긴 답변은 여러 청크로 분할하되 각 청크에 질문을 반복하고 동일 Q&A 문서 버전에 연결한다. `kind=qa`로 구별한다.

## 8. 품질 검사와 승인

| 검사 | 기본 행동 |
|---|---|
| 유효 텍스트 0 | `empty_extraction` 실패, OCR 가능 여부 안내 |
| 깨진 문자 비율 1% 초과 | `needs_review` |
| 페이지 누락·순서 역전 의심 | `needs_review`, 원본 대조 |
| OCR·변환·표 복원 경고 | 관리자 승인 대기 |
| 청크가 상한 초과 | chunker 실패, 자동 잘라 적재 금지 |
| 위치 없는 청크 | 스키마 실패 |
| 개인정보 정책 위반 | 공개 지식 등록 차단 또는 마스킹본 검토 |
| 청크 0개 | 색인 작업 접수하지 않음 |

검사 임계값은 초기 정책이며 빈 표지 같은 정상 사례를 평가해 조정한다. 승인하지 않은 버전은 `desired_version_id`로 지정할 수 없다. 부분 페이지 실패를 허용하려면 누락 페이지를 사용자와 관리자에게 명시하고 별도 승인해야 한다. 기본값은 전체 문서 승인 전 공개하지 않는 것이다.

## 9. 구현 완료 증거

형식별 합성 파일과 예상 추출 위치를 테스트 fixture로 보관한다. 처리 결과에는 원본 해시, 파서 버전, 블록·청크 수, 경고, 검토자·검토 시각이 있어야 한다. 임의로 선택한 청크 10개를 원본 위치와 대조하고 표의 수치·단위·음수가 유지되는지 확인한다. 원본 PDF 없이 청크만 있는 이관 자료는 `imported_text`로 구별하고 페이지 정확성을 새로 보증하지 않는다.
