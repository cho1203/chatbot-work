# 삼광 설비 챗봇 — 고장수리내역 검색 방식 비교

> **GUIDE_13 — 9번의 고장수리내역 설계를 기준틀로 두고, 검색·표시 방식 3가지 안을 비교한 문서.**

1. **범위**: 고장수리내역(엑셀) 검색·표시 방식만 다룬다. 매뉴얼·작업지시서는 다루지 않는다.
2. **기준**: 9번·10번이 최종본이다. 이 문서는 "검색 방식을 어떻게 가져갈지" 논의·결정을 위한 비교 자료이고, 결정되면 9번 0.5·1.2절에 반영한다.
   - **반영 완료(2026-10-13)**: 방식 B(하이브리드)는 9번 0.5절에, 방식 C(원본 시트 보기)는 9번 1.1·1.2·1.6절에 반영됐다. 이 문서는 그 **근거·비교**로 남겨둔다.
   - **철회(2026-10-13)**: ③번 유사목록 폴백(설비명 일치 없을 때 다른 설비 사례를 유사 목록으로 보여주는 것)은 **데모 범위에서 뺐다** — 고장수리내역은 안전과 직결되는 정보라, 다른 설비 사례가 잘못 적용될 위험이 "유사 사례를 보여주는 편의"보다 크다고 판단. 설비명이 있는데 그 설비 사례가 없으면 그냥 `NOT_FOUND`다(9번 1.5절 시나리오 13번). 3부 프로덕션에서 경고 UI 등을 신중히 설계한 뒤 다시 고려한다(3부 3.3절).
3. **전제**: 아직 아무것도 구현·테스트하지 않았다(9번 전제와 동일). 아래 장단점은 설계·로직상 추론이지, 실측값이 아니다.

## 0. 지금 9번에 있는 틀 (기준선)

| 단계 | 내용 |
|---|---|
| 데이터 | `설비 수리 보고서.xlsx`, 40시트 = 사례 40건 |
| 색인 | 라벨 기반 파싱 → **시트 1개 = 청크 1개**(`repair_log_s{순번}`) |
| 검색 대상(`text`) | `{장비명} {이상부위} {고장현상}` 결합 문장만 — `조치내용`·부품 등은 `metadata`로만 저장, 검색엔 안 쓰임 |
| 검색 로직 | `equipment`(설비명) 질의어 포함 시 하드 필터 → `doc_type='repair_log'` 범위에서 **벡터 유사도** → `rank_by_type` 상위 3개 |
| 표시 | GITC가 다듬은 `answer` + `metadata`에서 꺼낸 원본 필드값(조치내용·부품 등) 근거 카드 |

이게 지금까지 9번에 적힌 **방식 A**다. 아래 B·C는 이번 대화에서 나온 대안이다.

## 1. 방식 A — 지금 설계 그대로 (벡터 단독)

**어떻게 찾나**: 질문을 벡터로 바꿔서, `text`(결합 문장) 벡터들과 코사인 유사도 비교. 설비명이 질문에 있으면 그것만 먼저 하드 필터.

| 장점 | 단점 |
|---|---|
| 구현이 가장 단순 — 지금 9번 설계 그대로 | 코드·부품번호 같은 **정확 일치**가 약함(임베딩은 "의미 비슷함"엔 강하지만 "글자 정확히 같음"엔 약함) |
| 표현이 달라도 의미가 비슷하면 찾아냄("베어링 흔들림"↔"스핀들 진동") | `조치내용`이 검색 대상이 아니라서, 조치 내용 기반 질문("베어링 교체 사례")은 처음부터 범위 밖 |
| 매뉴얼·엑셀 검색 로직을 그대로 재사용(일관성) | 40건뿐인 작은 데이터셋이라 벡터 순위 차이가 노이즈에 가까울 수 있음 |

## 2. 방식 B — 하이브리드 (키워드 정확 매칭 + 벡터 유사도)

**어떻게 찾나**: 2단계로 나눔.
1. `equipment`·부품명·코드처럼 **정확히 일치해야 하는 값**을 먼저 키워드로 거른다
2. 그 후보 안에서만 **벡터 유사도**로 재순위(방식 A의 로직 재사용)

| 장점 | 단점 |
|---|---|
| 정확히 맞아야 하는 건 놓치지 않고, 표현이 달라도 의미가 비슷한 건 찾아냄 — A의 약점 보완 | 추가 구현 필요: 부품명·코드 추출 로직, 2단계 쿼리 조합 |
| 작은 데이터셋(40건)에서 특히 유리 — 정확 매칭으로 먼저 좁히면 벡터 순위의 노이즈 영향이 줄어듦 | 어떤 필드를 "정확 매칭 대상"으로 할지 기준을 새로 정해야 함(지금은 `equipment`만 하드 필터) |
| 9번 3.13절에서 매뉴얼 쪽에 이미 제안한 `anchors`(코드·번호 정확 일치) 설계와 같은 방향이라 설계 일관성 있음 | `조치내용`을 검색 대상에 넣으려면 `text` 구성 자체도 같이 바꿔야 함 |

## 3. 방식 C — 통으로 넣는 방식 (원본 시트 그대로 보여주기)

**어떻게 보여주나**: 검색은 A나 B로 후보를 찾되, **근거는 파싱된 필드값이 아니라 원본 시트를 PDF/이미지로 변환한 것 자체**를 보여준다. 매뉴얼의 "원본 PDF 보기"와 같은 원리.

| 장점 | 단점 |
|---|---|
| **파싱 오류 가능성이 0** — 라벨 기반 파싱이 셀 값을 잘못 읽었더라도 원본 자체는 틀릴 수 없음. 정확도가 생명인 고장수리내역에 가장 안전 | 엑셀 시트를 보이는 형태(PDF·이미지)로 **미리 변환하는 도구가 아직 설계에 없음** — `openpyxl`은 셀 값을 읽는 라이브러리라 서식 그대로 렌더링은 못 함(LibreOffice 헤드리스 변환 등 별도 도구 확인 필요) |
| 사용자가 직접 원본을 눈으로 확인 가능 — "GITC가 틀리게 요약했나?"를 바로 검증 가능 | 검색 자체의 정밀도는 여전히 A 또는 B에 의존함 — C는 "찾은 다음 보여주는 방식"이지 "찾는 방식"의 대안이 아님 |
| 9번 3부 3.5절("문서 열람")에 이미 요구사항으로 있던 내용과 같은 방향 | 변환·저장 비용 추가(사례 40건×PDF 1개씩 미리 만들어둬야 함) |

## 4. 비교표

| 항목 | A: 벡터 단독 | B: 하이브리드 | C: 통짜 원본 보기 |
|---|---|---|---|
| 해결하는 문제 | 기본 검색 | A의 "정확 일치 약함" 해결 | 파싱·요약의 신뢰도 문제 해결 |
| 구현 난이도 | 낮음(이미 설계됨) | 중간(필드 추출 로직 추가) | 중간~높음(렌더링 도구 필요) |
| 정확도 리스크 | 코드·조치내용 질문 놓칠 수 있음 | A보다 낮음, 여전히 "찾아내는 것" 자체의 리스크는 있음 | 보여주는 내용 자체는 리스크 없음(원본이므로) |
| 작은 데이터셋(40건) 적합성 | 보통 | 좋음 | 무관(표시 방식이라 검색 정밀도와 별개) |
| 데모 범위 적합 | 그대로 적합 | 추가 설계 필요하지만 데모 범위 내 가능 | 변환 도구 확인 전까진 3부(프로덕션) 권장 |

## 5. 결론 — A·B·C는 서로 배타적이지 않다

세 방식은 **"어떻게 찾을지"(A/B)**와 **"찾은 걸 어떻게 보여줄지"(C)**로 레이어가 다르다. 그래서 같이 쓸 수 있다.

**주의 — C는 "잘 찾는 것"과 무관하다.** C는 검색 단계에 전혀 관여하지 않는다 — 찾아온 사례를 원본 그대로 보여줄 뿐이다. 그래서 **검색을 A(약한 쪽)에 그대로 두고 C만 적용하면 오히려 위험**하다 — 틀린 사례를 찾아놓고도 "원본 그대로"라는 이유로 사용자가 더 신뢰하게 될 수 있다(원본을 보여준다는 것 자체가 신뢰를 더 주기 때문에, 정작 고르는 단계가 틀렸으면 더 그럴듯하게 틀린 답이 된다). **C는 반드시 B와 같이 써야** "정확하게 찾고(B) + 확실하게 보여주는(C)" 조합이 완성된다.

**추천 조합(확정, 9번에 반영됨)**: **검색은 B(하이브리드)**로 후보를 찾는다 — 설비명이 질의어에 있으면 정확 일치 하드 필터, 없으면 `doc_type='repair_log'` 전체에서 의미 유사도(9번 0.5절). **단, 설비명은 있는데 그 설비 사례가 없으면 다른 설비로 대체하지 않고 `NOT_FOUND`다** — 유사목록 폴백은 안전 문제로 데모에서 뺐다(위 "철회" 참고). **근거 표시는 C(원본 시트 보기)**로 찾아온 사례를 원본 PDF 그대로 보여줘서 신뢰도까지 확보한다(9번 1.2절 7번, 1.6절 "원본 시트 보기 버튼").

## 6. 아직 안 정해진 것 (9번에도 "확인 필요"로 남겨둠)

- 하이브리드(B)에서 `equipment` 외에 부품명·코드도 "정확 매칭 대상"에 넣을지(9번 0.5절에 확인 필요로 명시)
- `text` 구성에 `조치내용`을 포함시킬지, 포함시키면 임베딩 문장이 너무 길어지진 않는지 — 아직 결정 안 됨, 9번 `text` 구성은 지금도 `{장비명} {이상부위} {고장현상}`만
- C를 위한 엑셀→PDF 변환 도구 선정(LibreOffice 헤드리스 등 후보, 9번 1.2절 7번에 확인 필요로 명시)
